# ubitofu 0.10 Cutover Design

Date: 2026-08-03
Status: approved for implementation

## Goal

Replace the current reconciliation pipeline with one coherent ubitofu 0.10
implementation. Release it once, then update Ansible once and remove the old
integration machinery.

ubitofu remains a Python, plan-only Unix tool. It generates HCL from a live
UniFi controller, captures later UI or mobile changes to safely comparable
settings, and prevents conflicting HCL and controller changes to the same
comparable value from silently choosing a winner. Secret values are a deliberate
exception: ubitofu renders secret-manager references but never captures a secret
from the controller into HCL.

## Delivery rule

The implementation may use small commits and ordinary tests, but production has
one code path throughout the release:

- no legacy writer
- no shadow CLI or feature flag
- no duplicate source or module index
- no compatibility aliases
- no intermediate public release
- no Ansible dual-run period

The completed implementation ships in the existing `0.x` series, provisionally
as 0.10.0. Compatibility with earlier CLI behavior and exit codes is not
required.

## Architecture

```text
controller adapter   OpenTofu adapter   HCL module index
        \                 |                 /
         +-------- immutable snapshot -----+
                          |
                  pure three-way planner
                          |
                    ReconcilePlan
                          |
                 render all files in memory
                          |
             structural checks and transaction
```

`pipeline.py` becomes a small composition root. It does not classify resources,
scan HCL, interpret raw JSON, or write individual files.

### Trustworthy boundaries

The controller and OpenTofu adapters validate every external document before it
enters the semantic model. Only `tofu plan -detailed-exitcode` accepts exit 2.
All other OpenTofu commands require exit 0. Errored or malformed JSON fails
closed. Normal diagnostics are bounded and redacted.

OpenTofu 1.12 fresh-create plans may omit `prior_state`; ubitofu accepts that
only when every managed change is structurally an all-create change with null
`before`, a present `after`, and no drift. Any other missing prior state blocks.
A root sensitivity mask of `false` means an empty mask. Nested `false` values,
string masks, and other malformed sensitivity shapes block before normalization.

TLS verification defaults on and supports a custom CA bundle. Private plans,
generated stubs, transaction data, and receipts use private permissions. One
workdir session owns their cleanup and holds the advisory lock from recovery
through command completion.

### One semantic model

The planner compares three evaluated values retained in the plan:

- `base`: last managed values from the saved plan's embedded `prior_state`
- `desired`: evaluated configuration from the plan's `after` values
- `plan_live`: refreshed remote values from the plan's `before` values

For reconcile, `plan_live` is the live semantic value because the command just
created the plan. For saved-plan check, one sequential controller collection
window is normalized into provider-comparable `live_at_check` values. Check
blocks when a collected value differs from `plan_live`, or when a managed value
cannot be normalized safely. It never substitutes the current backend state
for the saved plan's embedded base.

`controller_projection.py` makes that normalization explicit. It matches raw
controller records to provider addresses through the manifest identity rules,
then projects only declared controller-owned fields through the same schema-aware
cleaning and normalization used by generation. The manifest owns exceptional
field mappings and coercions. Both plan-time and fresh values are reduced to the
same declared comparable paths. A missing identity, unprojectable managed path,
ambiguous mapping, or incomplete endpoint blocks check instead of silently
reducing coverage.

Direct controller discovery also supplies endpoint coverage and UniFi data
unavailable through the provider. The planner does not evaluate HCL expressions
itself.

Independent changes merge. Equal changes converge. Different changes to the
same managed value block the whole reconcile with no file writes. Collections
merge only when a resource-specific policy declares a stable element identity.
The public resource manifest owns those policies. Other complex collections are
atomic and block when both sides changed.

Sensitive and write-only values have a separate, value-free decision table.
Snapshot normalization may compare private plan values transiently using the
provider schema and OpenTofu sensitivity masks, but the resulting observation
retains only the sensitive path and one typed fact:

| Plan-time fact | Reconcile behavior |
| --- | --- |
| all equal | suppress the value and report no managed change |
| HCL only changed | preserve the IaC/secret-manager intent |
| controller only changed | block as attention because the value cannot be captured |
| both changed identically | treat the change as converged |
| both changed differently | block as a secret conflict with no writes |
| value is unavailable or write-only | mark it noncomparable; block apparent live/conflicting change and otherwise report the limitation |

No retained reconciliation observation, edit, candidate, outcome, receipt,
diagnostic, or digest contains a secret value or a fingerprint of one. The
external plan is a private runtime input and its secret values are discarded
after the typed facts are derived. Controller projection never claims that a
masked, omitted, or differently encoded secret is comparable.

Computed and unknown values do not become drift. The model retains complete
module, index, data, and deposed addresses. Legal addresses that cannot map to
one source block become blocking attention. Expanded instances never delete a
shared resource block. A planned managed-device create remains forbidden
because device adoption belongs in the controller UI.

### One HCL index

tree-sitter-hcl 1.2.0 with tree-sitter 0.26.0 indexes active `.tf` and `.tofu`
files, resources, attributes, imports, variables, and qualified references. It
rejects parser recovery nodes. Edits splice verified byte spans and preserve
every unselected byte.

The same module index implements OpenTofu file precedence. JSON configuration is
discoverable but read-only in 0.10. Drift requiring a JSON edit blocks
reconcile.

python-hcl2 remains pinned only as the serializer inside the ubitofu-owned HCL
renderer. It never parses operator HCL or decides source ownership. It can be
removed only when a replacement serializer passes the renderer corpus,
structural reindex, formatting, secret-reference, and byte-stability gates.

### One generation preview

Generation follows the same shape as reconciliation without pretending it is a
three-way merge. One immutable snapshot contains controller discovery, provider
schema, effective module, imports, variables, coverage findings, and source
identities. Pure helpers render every resource, import, variable, and coverage
candidate in memory. The complete candidate module is structurally checked
before the shared transaction can start. Failed OpenTofu output or blocking
coverage leaves no committable preview and makes no lasting generated
destination change.

Generation chooses one source extension for every owned artifact; an active
`.tofu` file selects `.tofu`, including in a mixed root, otherwise it uses
`.tf`. Provider-schema sensitivity and write-only metadata are applied
recursively through nested attributes and blocks. A nested sensitive value is
suppressed and adds lifecycle ignore coverage for its top-level root; only an
explicit top-level secret rule may emit a variable reference.

An existing `COVERAGE.md` is captured as a detached source identity before
rendering. ubitofu replaces it only when the ownership marker is exact and the
captured identity is still current; unmarked operator content blocks generation.
The serializer's aggregate output receives only a pure, bounded in-memory
whitespace-alignment pass. Operator-owned HCL is never passed through that
formatter.

OpenTofu only generates provider-shaped configuration when import blocks are
physically present in its root module. It has no in-memory configuration overlay.
Generation therefore uses one reserved, short-lived `ubitofu-imports.tf`
scaffold while holding the workdir lock. ubitofu writes and fsyncs the complete
mode-0600 scaffold privately, records its hash and filesystem identity, then
publishes it atomically with a same-filesystem hard link immediately before
`tofu plan`. The root link is verified, removed, and its directory fsynced in
the plan cleanup path before any plan JSON is interpreted. A handled failure
leaves no scaffold. A crash may leave only the exact recoverable scaffold. The
next invocation removes it only when its path, inode, type, owner, mode, and
hash match the durable private manifest. Any mismatch blocks and preserves the
evidence.

The reserved path is never a legal renderer candidate or transaction
destination, and the transient name is ignored by Git. Runtime manifest version
2 is the scaffold inode-and-digest protocol; other versions are preserved and
rejected rather than interpreted or cleaned.

`generate` requires exclusive use of the OpenTofu root for its duration. The
ubitofu lock excludes other ubitofu processes but cannot prevent an unrelated
OpenTofu, Git automation, or file watcher from observing the transient import
file. Operators must not run those concurrently. This exception is confined to
initial generation: `reconcile --dry-run` never publishes the scaffold or any
other root-level temporary file.

### One transaction path

Every candidate file is rendered before the first write. The transaction:

1. holds one advisory workdir lock
2. rejects escaping paths, symlinks, and non-regular destinations
3. rechecks captured file hashes and identities
4. parses every candidate HCL file and formats ubitofu-owned output
5. writes and fsyncs same-directory temporary files and complete backups
6. rechecks each destination immediately before its journaled replacement
7. journals intent, replaces destinations, and fsyncs affected directories
8. rolls back completed replacements when commit fails
9. recovers at next startup or quarantines ambiguous state without further writes

Success yields the complete candidate tree. A failed commit with successful
rollback yields the complete original tree. Missing or ambiguous recovery data
is preserved privately and blocks later mutation until an operator resolves it.

The threat model is an administrator-owned worktree. It covers crashes,
concurrent ubitofu processes, stale snapshots, path mistakes, and external edits
detected by the final per-file identity check. An unrelated process writing
during the subsequent replacement window is outside the guarantee, as is a
hostile local process racing filesystem syscalls. Directory file descriptors
and `openat`-style traversal are not required.

Existing files preserve POSIX mode, uid, and gid. The worktree owner must own
every file ubitofu edits. A small macOS/Linux metadata adapter inspects ACLs,
extended attributes, and platform file flags before preparation and again at the
per-entry stale check. Version 0.10 refuses preservation-relevant metadata and
any fact it cannot classify. Two exact OS-managed storage facts are excluded:
Darwin's `com.apple.provenance` xattr and Linux's `FS_EXTENT_FL`. Every other
xattr or file-flag bit remains blocking. It does not silently discard metadata
it cannot preserve. A blocking diagnostic names the affected relative path and
the exact ACL, extended attribute, or file-flag fact when available.

The staged-validation spike remains evidence, not runtime architecture. A
private evaluation-root spike proved that moving the root changes local backend,
local-module, tfvars, auxiliary-file, and `path.*` semantics. Version 0.10 does
not reconstruct that root or OpenTofu's dependency cache and does not require a
kernel network sandbox. Direct controller-to-schema generation is also excluded:
the provider performs read conversions and defaults that the schema and current
manifest do not encode. OpenTofu remains the generation semantic oracle.
Tree-sitter parsing, anchored edits, candidate hashing, and transactional
replacement protect source writes.

### Bounded sequential plan checks

`ubitofu check` reads exactly the saved plan supplied by the caller. It uses the
plan's embedded prior state as `base`, the plan's `before` values as
`plan_live`, and a fresh normalized controller observation as `live_at_check`.
It never runs `tofu plan`, substitutes current backend state as the base, or
writes HCL.

Its receipt includes digests for the saved plan, active source, plan-time live
view, and fresh canonical controller observation. OpenTofu's saved-plan apply
owns backend lineage and serial enforcement because plan JSON does not expose
those fields. ubitofu neither guesses them nor parses raw backend state.
Authorization covers the controller values observed during one sequential
collection window. Without a controller revision token, a value can change
after its endpoint was read and remain undetected, including before check
returns. Sensitive and write-only paths have a further explicit limitation:
the current controller manifest has no policy proving that controller and
provider secret representations are equivalent. `check` therefore emits
`secret_freshness_unverified` for a changed secret-bearing resource and does not
claim to authorize post-plan UI secret changes. Applying such a plan can
overwrite a secret changed in the UI after planning. The external workflow
runs backup and pre-apply health capture first, then check immediately before a
final digest verification and apply of that same file.

## Public CLI

Version 0.10 exposes only:

```text
ubitofu generate
ubitofu reconcile
ubitofu reconcile --dry-run
ubitofu check --plan PLAN
ubitofu inspect
ubitofu health snapshot
ubitofu health compare --before RECEIPT
```

`enumerate`, `verify`, and `reconcile --check` are removed. The replacement
`reconcile --dry-run` is a first-class interface, not a compatibility alias. It
collects the same snapshot and computes the same plan, candidates, decisions,
changed paths, and candidate digests as wet mode. It performs no HCL transaction
and leaves every destination byte unchanged.

Exit codes are command-independent:

| Code | Meaning |
| ---: | --- |
| 0 | command succeeded or plan is allowed |
| 1 | operational failure |
| 2 | command-line usage error |
| 3 | valid blocking outcome: conflict, unsafe plan, or health degradation |

Advisory warnings exit 0 and appear in human and JSON output. Reconcile writes
nothing when any blocking decision exists. An external reconcile workflow uses
the Git diff, not a special exit code, to decide whether there is a change to
publish.

`--output PATH` creates a new file or atomically replaces an existing regular
file owned by the worktree owner and forces mode 0600. It refuses symlinks,
non-regular files, ownership mismatches, and unsafe parent paths.

## Product boundary

ubitofu owns controller discovery, schema-aware generation, reconciliation,
structural source edits, plan safety decisions, health interpretation, and
human or JSON results.

It owns secret-reference rendering and value-free secret-change classification,
not secret storage or controller-to-HCL secret capture. Deployment credentials
and secret values remain in the consumer's secret manager. Saved-plan check
cannot freshly compare sensitive paths without a manifest policy proving their
representations equivalent.

It does not write the controller, apply OpenTofu plans, mutate state, back up a
backend, manage deployment variables, commit to Git, open pull requests, detect
a CI vendor, schedule work, or send notifications.

## Verification

The release branch uses ordinary tests while it is built. These tests do not
create a second production path:

- exhaustive planner decision tables and properties
- parser corpus and byte-preservation properties
- adapter tests for malformed controller and OpenTofu input
- transaction failure and process-interruption tests
- CLI and receipt contract tests
- real OpenTofu integration tests
- package installation tests on supported Python and operating-system targets
- selected controller scenarios
- mutation tests for the planner, parser adapter, and transaction

The package declares `requires-python = ">=3.11,<3.15"`. The supported baseline
is CPython 3.11 through 3.14 on macOS and Linux. The
release matrix covers every Python version on Linux x86-64, both boundary
versions on macOS arm64, and Python 3.11 on Linux arm64. Other POSIX
architectures are best effort. Windows is unsupported in 0.10 because the lock
uses `fcntl`.

The tested OpenTofu line is 1.12.x. OpenTofu JSON format major version 1 is
accepted with strict validation of used fields. Unknown minor fields are
ignored.

The branch releases only after the complete 0.10 command surface uses the new
architecture and the old production implementation has been deleted.

## Ansible cutover

After 0.10.0 is released, the final image build context is prepared without
committing or deploying consumer changes. The deployment image is built and
verified with the released package under a new immutable tag and digest. One
Ansible change then:

1. pins every affected job to that exact image digest
2. updates the pinned ubitofu version
3. commits the non-secret ubitofu configuration
4. creates one saved plan
5. backs up state externally
6. captures a pre-apply health snapshot
7. runs `ubitofu check` against that plan
8. verifies the saved-plan digest
9. applies the same saved-plan file
10. compares post-apply health with the saved baseline
11. keeps Git publication, PR creation, scheduling, secrets, and notifications
12. deletes the old UniFi gate, health parser, temporary config, compatibility
   exit mapping, and redundant installation code

There is no dual-run period. Rollback is a Git revert of the Ansible cutover and
its version pin, not a runtime compatibility path in ubitofu.

The cutover preserves the pre-apply backup gate, UI-only device-adoption block,
and baseline-versus-new health-degradation rule. Failure to capture the baseline
blocks apply. A newly unknown health state blocks. An unchanged unknown baseline
is advisory. A trap removes the private plan and receipts on every handled exit.
Deployment secrets remain in the consumer. Synthetic consumer contract tests
replace the deleted shell parsers without copying private values into the public
repository.

## Acceptance criteria

- Every command uses the new adapters, snapshot, planner, index, and transaction.
- No old reconciliation writer or compatibility CLI remains.
- Generate and reconcile either commit the complete candidate set or leave the
  original worktree recoverable.
- Different controller and HCL changes to the same safely comparable field, or
  to the same detectable sensitive field, block without writes.
- From equivalent snapshots, wet and `--dry-run` reconciliation produce
  identical plans, candidate bytes, decisions, changed paths, and candidate
  digests. Dry-run writes no HCL.
- `check` inspects only the supplied plan and reports its digest.
- Human and JSON output derive from the same result.
- The released package installs and passes the supported test matrix.
- The single Ansible cutover applies the exact checked plan and contains no old
  UniFi plan or health parser.
- No deployment or repository automation enters ubitofu.
