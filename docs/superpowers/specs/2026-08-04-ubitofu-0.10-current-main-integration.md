# ubitofu 0.10 current-main integration

Date: 2026-08-04
Status: verified local release candidate

The 0.10 branch originally started before the 0.8 and 0.9 releases. The final
cutover therefore merges current main and resolves it at the product boundary
instead of shipping from the older base or restoring both architectures.

## Ported into 0.10

- Custom AP groups are enumerated and generated. The built-in `All APs` group
  remains an explicit controller-owned exclusion.
- Controller tests use digest-pinned images, a pinned provider, the image's
  `/readyz` contract, the owner-seeded UniFi OS API key, and the pinned device
  herder. Adopted emulated devices reach the provider-shaped generation
  snapshot. Known coverage gaps still suppress every candidate and write.
- `tofu fmt` failures use the 0.10 typed, redacted operational error rather
  than falling through as an unexpected exception.
- The 0.8 and 0.9 release history remains in the changelog.

## Superseded by the 0.10 architecture

- Declared scalar, collection, and nested-block intent is indexed by the one
  tree-sitter module index and compared by the three-way planner. The 0.9
  declaration scanner and surgeon are not retained.
- Managed existence, data-source exclusion, unknown values, replacements, and
  expanded instances are typed snapshot and planner facts. The 0.8 legacy
  existence classifier is not retained.
- The former command-specific exit band is replaced by the documented common
  0/1/2/3 contract and versioned receipts.

## Intentionally removed

- `migrate` and its schema-diff baseline are outside the seven-operation 0.10
  product surface. Provider upgrades remain OpenTofu and deployment-workflow
  responsibilities. There is no compatibility alias.
- The optional provider-contract sidecar binds one provider binary, schema
  exporter, and external catalog. It is deployment-specific evidence rather
  than a general live-controller-to-HCL interface, so it is not part of the
  open-source runtime. Provider documents consumed by 0.10 are still validated
  and digested at their adapter boundary.
- The legacy HCL surgeon, reporter, reconciliation pipeline, and their tests
  remain deleted. Current-main integration does not reintroduce a second
  writer, planner, report model, or CLI path.

## Release evidence

The integrated tree passed the supported Python and Linux architecture matrix,
strict static checks, parser and transaction proofs, wheel and source
distribution installs, and the live controller matrix. The controller run
completed 17 scenarios, with the real-PoE and apply-backed cases explicitly
skipped rather than counted as evidence. Apply-backed scenarios remain parked
until both provider import defects and incomplete supported controller coverage
are closed.

The package boundary was checked from an exact committed-tree archive. Clean
wheel and source-distribution environments on Python 3.11 and 3.14 imported
ubitofu and its tree-sitter dependencies, exposed the CLI, and reported version
0.10.0. Linux x86-64 passed on Python 3.11 through 3.14. Linux arm64 passed on
Python 3.11. The native macOS suite, Ruff, strict mypy, mutation configuration,
actionlint, parser proofs, staged-validation proofs, and the branch secret scan
also passed.

## Final adversarial verdict

Verdict: GO for an untagged local 0.10 release candidate. No Critical or
Important architecture finding remains.

The final review traced each public operation through the composition root and
confirmed that 0.10 has one controller adapter boundary, immutable snapshot,
pure planner, in-memory renderer, and transaction path. In particular,
`reconcile --dry-run` and wet reconcile produce the same decisions and candidate
digests for equivalent snapshots. Only wet reconcile may prepare and commit the
rendered candidate set. Blocking plans suppress every edit. The ported 0.8 and
0.9 behavior feeds these boundaries rather than retaining their former writer,
reporter, existence classifier, or provider-contract sidecar.

Two proof limits are explicit and are not counted as green tests:

- The full mutation sweep remains server-only. Running it for this exact head
  requires publishing a ref, which is outside the local-candidate boundary.
- Apply-backed controller scenarios remain parked for the provider and coverage
  defects documented above. The tested controller matrix proves collection,
  adoption, projection, fail-closed coverage, and generation without claiming
  a live apply proof.

Neither limit adds transitional machinery or weakens `reconcile --dry-run`.
The release workflows remain intentionally untouched: publishing a `v*` tag
would trigger external release behavior and is not part of this local proof.
